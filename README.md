# GlanceAI

**One glance, one answer.** GlanceAI is an AI assistant for the Even Realities G2 smart glasses, built for the **Heads Up: Even Realities Hackathon** (DoraHacks), track **04 · AI Assistants & Work**.

Ask a question and the answer comes back as a single big-type card on the glasses — a few words, readable in one glance, no phone needed. Two glance panels ride along: the top 3 live news headlines, and BTC / ETH prices on one line each.

## What it does

- **Ask AI** — Browse preset questions with temple swipes, tap to ask, and the answer appears as one short card. Or type a question in the phone-side companion page and the answer card is pushed to the glasses.
- **News** — The top 3 headlines right now, fetched live.
- **Prices** — BTC and ETH, one line each, with the source and time on screen. Read-only market data; the app never trades and gives no financial advice.

**Controls (G2):** swipe up/down = move · tap = select / refresh · double-tap = back · double-tap on the home screen = system exit dialog (SDK `shutDownPageContainer(1)`, as required by Even Hub QA).

## How it works

GlanceAI is a standard Vite + TypeScript web app. On the glasses it renders through the **Even Hub SDK** (`@evenrealities/even_hub_sdk`): one full-screen text container (576 × 288) updated with `textContainerUpgrade`, input via `onEvenHubEvent` (click / scroll / double-click). The same screen state machine also drives a **browser preview renderer** — open the app in a plain browser and the identical screens are drawn into a 576 × 288 green frame (click = tap, double-click = double tap, wheel / arrow keys = swipe), which is how the screenshots below were made.

```
src/
  main.ts    Screen state machine, SDK bridge renderer, browser
             preview renderer, input mapping, companion form
  brain.ts   Answer engine (LLM slot + built-in rule engine)
  data.ts    Live prices + headlines with fallback chains
  config.ts  Optional user-supplied LLM endpoint configuration
app.json     Even Hub manifest (network whitelist, no other permissions)
```

### The AI, honestly

The app ships with **no API key** and does **not** pretend to run a real LLM:

- **Default — built-in rule engine.** Answers preset questions, time/date, live BTC/ETH prices, the top headline, simple arithmetic, and a few canned explainers. Anything else gets an honest "local mode can't answer that" reply.
- **Optional — bring your own model.** Set `llmEndpoint` / `llmModel` / `llmApiKey` in `src/config.ts` to any OpenAI-compatible chat-completions endpoint (for example **OpenRouter**, listed in this track). Answers are then generated by that model, with a system prompt that forces short, glanceable replies, hard-clamped before display. Never commit a real key — the hackathon rules forbid it and a packaged app can be unpacked by anyone.

Voice input is intentionally out of scope: the SDK provides raw microphone audio and speech-to-text needs a self-hosted backend, which a 7-day, key-less demo should not fake. Questions are picked by swipe or typed on the phone instead.

### Data sources (all free, key-less, read-only)

| Panel | Sources, in order | Fallback behaviour |
| --- | --- | --- |
| Prices | Binance → OKX → Gate.io → CoinGecko public ticker APIs | First reachable source wins and is **named on screen** (some regions block some exchanges — e.g. Binance returns HTTP 451 from restricted locations). If all fail: "Prices unavailable", tap to retry. |
| News | Hacker News official API (top stories) | If unreachable, three bundled **sample** headlines are shown, explicitly labelled "(sample data – feed offline)" on screen. |

All domains are declared in `app.json`'s network whitelist, as Even Hub requires. The app requests no other permissions.

## Run it

Prerequisites: Node.js 18+.

```bash
npm install
npm run dev          # Vite dev server on http://localhost:5173
```

- **Browser preview:** open `http://localhost:5173` and interact with the green frame.
- **Even Hub simulator:** `npm install -g @evenrealities/evenhub-simulator`, then `evenhub-simulator http://localhost:5173`.
- **Real G2 glasses:** `npm install -g @evenrealities/evenhub-cli`, then `evenhub qr --url "http://<your-LAN-IP>:5173"` and scan with the Even Realities App (developer mode).
- **Production build:** `npm run build`
- **Package (.ehpk, optional submission artifact):** `evenhub pack app.json dist -o glanceai.ehpk --sdk-ver 0.0.14`

## Verification performed

- `tsc && vite build` passes against `@evenrealities/even_hub_sdk@0.0.14`.
- `evenhub pack` validates `app.json` and produces `glanceai.ehpk` (min_app_version 2.2.9 stamped for SDK 0.0.14).
- Full click-through of every screen in the browser preview with **live data**: the BTC answer and the Prices panel were served by OKX after Binance returned HTTP 451 (the fallback chain working as designed, source named on screen); the News panel showed live Hacker News headlines. Screenshots live in `../screenshots/` (outside the app package).
- The official simulator binary could not be launched in our Linux sandbox (missing system library `libwebkit2gtk-4.1.so.0`, and the package manager was locked by other processes), so simulator footage is still to be captured on a regular dev machine — the demo script in `../docs/demo-script.md` is written for that. In a plain browser the SDK's startup-page call returns an error, and GlanceAI detects that and falls back to the preview renderer instead of failing silently.

## What existed before Nov 23

Nothing. GlanceAI was designed and written during the hackathon build week. It uses only public, pre-existing building blocks: the Even Hub SDK and CLI/simulator, Vite, and the public APIs listed above.

## Feature requests for the APIs we used

1. **Even Hub SDK:** a documented "is a real bridge attached?" check. In a plain browser the SDK shim resolves `waitForEvenAppBridge()` and only the startup-page result code reveals there is no handler behind it.
2. **Even Hub SDK:** per-container font-size control for text containers — glanceability often wants one short line set much larger than body text.
3. **Even Hub simulator:** a built-in screenshot/capture command for the 576 × 288 canvas, to make demo videos and store listings reproducible.
4. **Hacker News API:** a single endpoint returning top story titles in one call; today it is one request for the ID list plus one request per story.
